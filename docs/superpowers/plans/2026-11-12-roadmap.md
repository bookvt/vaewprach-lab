# vaewprach-lab — ลำดับการทำงาน (Build Order)

**Spec:** [`README.md`](../../../README.md)

เอกสารนี้บอกว่า **ทำอะไรก่อน-หลัง และทำไม** แต่ละ step คือ 1 PR (หรือ 1 ชุดงานมือ) ที่จบแล้วตรวจได้จริงบน cloud
แต่ละ phase จะมี implementation plan ละเอียดของตัวเอง เขียนตอนเริ่ม phase นั้น (ไม่เขียนล่วงหน้าทั้งหมด เพราะสิ่งที่เจอใน phase ก่อนจะเปลี่ยนรายละเอียดของ phase ถัดไป)

สัญลักษณ์: 👤 = คุณทำเอง (สมัคร account, กดใน console, approve) · 🤖 = เขียน code / config ใน repo

## หลักการเรียงลำดับ

1. **Security ก่อน code** — repo จะเป็น public จึงต้องมีตัวกัน secret หลุดก่อนมี secret ตัวแรก
2. **ของที่ตัวอื่นพึ่งพาทำก่อน** — state backend → network → VM → K3s → Argo CD → ทุกอย่างที่เหลือ
3. **ทุก step ต้อง rebuild ได้จาก Git** — ถ้าต้องกดมือ ต้องจดใน runbook
4. **เปิด service สู่ internet ให้ช้าที่สุด** — มี TLS + auth ก่อนค่อยเปิด
5. **สมัคร SaaS ตอนที่ต้องใช้** — ไม่สร้าง credential ทิ้งไว้ล่วงหน้า
